## 🗺️ Learning Path

The program moves in four phases — each one building directly on the last.

| Phase | Months | What you learn |
|-------|--------|----------------|
| 🟢 **Foundation** | 1–4 | HTML, CSS, Tailwind, JavaScript fundamentals, async/APIs |
| 🔵 **Frontend** | 5–8 | React, TypeScript, routing, state, testing |
| 🔴 **Backend** | 9–10 | Node.js, Express, PostgreSQL, Docker, JWT auth |
| 🟠 **Fullstack** | 11–12 | Ship a real product, deploy it, get job-ready |

## 📅 Weekly Structure

Every week follows the same rhythm:

```
Weekend  →  Teaching + Live Coding (2–3 hrs)
Weekdays →  Assignment work (at your own pace)
End of week → Submit code to GitHub + receive feedback
```

**Always:** Teach → Build → Review

---

## 🧠 Evaluation

| Component | Weight | Description |
|-----------|--------|-------------|
| **Projects** | 50% | Quality of what you build and ship |
| **Weekly Submissions** | 40% | Consistency — showing up every week matters |
| **Participation** | 10% | Questions, code reviews, helping others |

<Callout type="info">
  Projects carry the most weight because that's what gets you hired. Recruiters look at your GitHub and deployed apps — not your homework streak.
</Callout>

---

## ⚠️ Program Rules

- Miss **3 or more unexcused submissions** → a warning, then review for removal. Life happens — communicate early.
- **Don't submit code you can't explain.** You should be able to walk through every line. Reading docs, studying patterns, and using references is normal — not being able to explain what you submitted is not.
- All code must be **pushed to GitHub** with meaningful commit messages.
