# フルスタックアプリの設計

コードを1行も書く前に、何を作るかを明確にします。これが最も重要なステップです。

<Callout type="warning">
  「とりあえずコードを書き始める」は失敗の最短ルートです。設計に1〜2時間使うことで、後で何週間も節約できます。
</Callout>

## ステップ1：コアな問題を1文で定義する

```
悪い例：「ブログアプリを作りたい」
良い例：「ライターが記事を投稿・管理でき、読者がカテゴリでブラウズしてコメントできるプラットフォームを作る」
```

## ステップ2：ユーザーを定義する

誰がこのアプリを使うか？ロールごとに何ができるか？

```
ゲスト:    記事を読む、カテゴリでブラウズ
ライター:  ゲストの全機能 + 記事の作成・編集・削除
管理者:   ライターの全機能 + ユーザー管理
```

## ステップ3：コア機能を優先順位付け

```
Must Have（MVP）:
  - ユーザー登録・ログイン
  - 記事のCRUD
  - 記事一覧・詳細表示

Should Have:
  - カテゴリ・タグ
  - コメント
  - 画像アップロード

Nice to Have:
  - 検索
  - いいね
  - メール通知
```

<Callout type="info">
  MVPから始めてください。すべての機能を一度に実装しようとするとプロジェクトは完成しません。最初はコアな機能だけを動かすことに集中しましょう。
</Callout>

## 演習

1. あなたのプロジェクトのコアな問題を1文で定義する
2. ユーザーロールとできることを箇条書きにする
3. Must Have / Should Have / Nice to Haveに機能を分類する
